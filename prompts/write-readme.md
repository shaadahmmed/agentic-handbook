# Write Readme

Use the [shared eight-line contract](README.md#shared-rules) and [project brief](project-brief.md). Risk, test and evidence definitions remain in their linked authoritative references.

Write README.md for {{PROJECT_NAME}}.
[PROJECT BRIEF] [COMMON RULES]

Sections in this order: title and one sentence purpose; status ({{STAGE}});
why it exists (2 to 3 sentences); features (short list); tech stack;
prerequisites with versions; quick start with exact commands from the brief
(clone, configure, install, run, test); documentation links (only to files
that exist); license ({{LICENSE}}).

Constraints: be concise. A new developer must be able to follow the quick start
without hidden steps; do not promise a fixed time without measuring it. Do not include architecture detail,
agent rules, changelog or roadmap content. Link to them instead.
After writing, run or dry-run the quick start steps where safe and report which
ones you could not verify.
